# 一筆帳裡的稅

日期：2026-09-22。狀態：待實作。

## 目標

加拿大的收據下面會列一堆稅（GST、PST／HST、罐裝的押金、環保費）。雪雪大人想在記帳時
把稅一起記下來，**目的是對帳**：之後翻這筆帳，看得出當時那張收據是怎麼加出來的。

使用者已確認的三件事：

1. 只要**一格**。收據下面所有稅、押金、環保費加起來填一個數字。
2. 金額欄的意思不變，還是**收據的總額（實付）**；稅只是註記其中有多少是稅。
3. 這格固定放在**金額下面**，不收合。

不做的事（使用者選項裡明確沒選）：稅率快捷鍵、押金另外追蹤與銷帳、統計頁的稅金合計、
GST 與 PST 分開記。`taxCents` 是這些東西的地基，日後要加不用重來。

## 資料

`Txn` 多一個欄位：

```ts
/** 這筆金額裡屬於稅的部分，整數分，與 amountCents 同一個幣別。沒填就是 undefined */
taxCents?: number;
```

- `amountCents` 不變：使用者付的總額。
- `actualCadCents` 不變：所有統計一律用它。**統計、預算、年報表、圖表都不用改。**
- 「稅前」＝ `amountCents − taxCents`，只在畫面上算，不存。存了就多一個會和另外兩個數字
  對不起來的欄位。
- 選填用 `undefined` 而不是 `0`：舊帳和「這筆真的沒有稅」都是沒填，不必分辨，
  而且 Sheet 上留白比一整排 `0.00` 好讀。

IndexedDB 不用 migration。Dexie 存的是整個物件，索引（`id, date, mainId, updatedAt`）沒動。

`NewTxnInput` 同樣多一個選填的 `taxCents?: number`，`addTxn` 與 `updateTxn(id, patch)` 照現有路徑帶過去。

## Google Sheet

紀錄頁多第 15 欄 **O「稅」**，接在現有的 A–N 之後。

- `TXN_HEADER` 尾端加 `'稅'`。
- `txnToRow` 第 15 個值：有稅寫兩位小數字串（和其他金額同一個 `amount()`），
  沒稅寫 `''`。
- `rowToTxn` 讀 `row[14]`：空白或缺這一欄就不放 `taxCents`。
- `syncEngine`：`TXN_RANGE` 從 `紀錄!A2:N` 改成 `紀錄!A2:O`，更新單列的範圍
  從 `紀錄!A${line}:N${line}` 改成 `:O${line}`。（`src/sync/syncEngine.ts:9,74,77`
  是整個專案唯三寫紀錄列的地方。）
- `createLedger` 的標頭從 `紀錄!A1:N1` 改成 `A1:O1`。

### 新舊版本並存是安全的

兩支手機不必同時更新，理由是現有的寫入範圍剛好幫了忙：

| 舊版 App 做的事 | 對 O 欄的影響 |
| --- | --- |
| 新增一筆（append `A2:N`） | O 留白，新版讀回來沒有稅。正確 |
| 修改一筆（update `A{n}:N{n}`） | 範圍碰不到 O，原本的稅**留著**。正確 |
| 讀取（`A2:N`） | 讀不到 O，舊版本來就不顯示稅。正確 |

唯一的損失是：舊版手機改過的那筆，它自己看不到稅、也不會去動它。可以接受。

### 現有帳本的標頭

已經存在的帳本 O1 是空的。App 在**第一次推送之前**補寫一次 `紀錄!O1 = '稅'`。

記住的方式是本機 meta 的 `taxHeaderSid`，存**寫過標頭的那本帳的 sid**，不是布林值：
一台手機可能登出後接到另一本舊帳本，布林旗標會讓第二本永遠補不到標頭。
`taxHeaderSid` 不等於目前接著的 sid 就寫一次，寫完存起來。

放在推送前而不是啟動時：沒有要推的東西就不必為了一格標頭多打一次 API。
`createLedger` 建的新帳本一開始就有標頭，建完直接把 sid 存進去。

## 記一筆面板

```
 $ 48.72                    CAD TWD USD
 主幣別 CAD · 直接記錄
┌────────────────────────────┐
│ 其中稅（可不填）        $ 2.85 │
│ 稅前 $45.87                  │
└────────────────────────────┘
 🍜 食   🚗 行   🏠 住 ...
```

- `AmountField`（`EntryDraft.field` 的型別）從 `'amount' | 'cad'` 變成 `'amount' | 'cad' | 'tax'`，
  草稿多一個 `tax: string`。點卡片切換焦點，用的是同一組鍵盤——和現在的「實際扣款 CAD」
  完全同一套機制，不新增互動概念。
- 卡片一直在，不收合（使用者選的）。它在金額列與幣別提示之後、`CategoryPicker` 之前。
- 稅是 0 或空白時**不顯示**「稅前」那行。金額還沒打時也不顯示。
- 外幣一樣能填，稅算在原幣上。此時面板上有三個數字欄位（金額／實扣 CAD／稅），
  鍵盤焦點三選一。實扣 CAD 不拆稅——那是銀行扣的錢，和收據上的稅是兩回事。
- 編輯模式：`draftFromTxn` 把 `taxCents` 帶回字串；沒有稅的舊帳帶成空字串，
  不會憑空生一個 0。
- 切幣別不清空稅（和清空 `cad` 不同）：稅跟著金額的幣別走，換幣別時金額本來就要重打，
  稅留著讓使用者自己改比清掉少一次意外。

### 版面高度

面板在短螢幕上本來就緊（v1.1.1 才把鍵盤改成 sticky dock）。這張卡片大約多 64px，
夾在金額和分類之間，捲動時會被捲過去，鍵盤仍然貼在底部。`e2e/entry.spec.ts` 已經有一個
375×700 的短螢幕案例（顯示放大的 15 Pro Max 就是這個高度量級），多了卡片之後它要照樣通過。

## 擋錯

| 情況 | 行為 |
| --- | --- |
| 稅留空 | 正常存檔，不記 `taxCents` |
| 稅 = 0 | 同上，當成沒填 |
| 稅 > 金額 | `canSave` 回 false，卡片下方出現「稅不能大於金額」 |
| 稅 = 金額 | 允許。稅前 $0 是合法的（例如只買了一個押金品項） |
| 金額 0、稅有值 | 本來就存不了（現有規則：金額 0 不寫入） |

稅不參與現有的「外幣要填實扣」規則。

## 哪裡看得到
