# 金額填稅前，而且只記 CAD

日期：2026-09-23。狀態：待實作。前一份相關設計：`docs/superpowers/specs/2026-09-22-tax-field-design.md`（v1.3.0 已上線）。

## 目標

v1.3.0 讓一筆帳可以記稅，但金額欄填的是收據總額、稅是「其中有多少是稅」。實際用起來不順：
加拿大的標價本來就不含稅，手上拿著的數字是稅前價。這次把輸入反過來——**金額欄填稅前，
右邊一格稅費，App 算出含稅合計**。

同時把目前用不到的多幣別介面拿掉。使用者原話：「外幣的功能目前用不到，只用的到 CAD，
之後其他貨幣的功能保留成未來可以擴展吧」。所以**拿掉的是介面，不是資料結構**。

### 使用者已確認的決定

1. 金額欄填稅前，右邊一張小卡「稅費」。金額下面那行從換算說明改成「金額請填稅前」，
   填了稅之後變成「含稅合計 $17.75」。
2. 幣別切換（CAD／TWD／USD）、「實際扣款 CAD」欄、明細列右下角的原幣小字，全部拿掉。
3. 新紀錄一律存成 CAD。編輯舊的外幣紀錄時帶入換算後的 CAD 金額，**原幣金額不保留**。
4. 明細列的金額加回錢字號（`-$16.75`）——原本不帶 `$` 是因為右下角標了幣別，那行沒了就得補上。
5. 收入不顯示稅費欄（2026-09-22 已確認：「收入也不用填稅」）。

## 存進去的是什麼

這是整份設計最容易搞混的一點，所以先講死：

| 畫面上 | 使用者打 16.75、稅費 1.00 | 存進去的欄位 | 值 |
| --- | --- | --- | --- |
| 金額 | 16.75（稅前） | `amountCents` | **1775**（＝稅前＋稅，實付總額） |
| 稅費 | 1.00 | `taxCents` | 100 |
| 含稅合計 | $17.75（算出來的） | `actualCadCents` | 1775 |
| —— | —— | `currency` | `'CAD'` |

**畫面上打稅前，資料存總額。** 理由：

- `amountCents` 從第一天起就是「這筆花了多少」，Google Sheet 的金額欄、年報表的 SUMIFS、
  統計、預算全部建立在這個意思上。改成存稅前會讓同一個欄位在同一份試算表裡前後兩種意思，
  對帳就毀了。
- 既有資料一筆都不用動，也不需要任何 migration。
- v1.3.0 這一天記的含稅帳（金額＝總額、稅＝其中的稅）打開來自動正確：
  稅前＝`amountCents − taxCents`，跟當初輸入的收據數字對得上。

考慮過的替代方案：`amountCents` 改存稅前、另外用 `actualCadCents` 存總額。否決——
那會讓 Sheet 的金額欄與實扣欄意思分裂，而且年報表的 SUMIFS 取的是實扣欄（F），
兩欄不一致時人在 Sheet 上對帳會先看到金額欄那個對不上收據的數字。

## 記一筆面板

```
 ┌──────────────────┐   ┌──────────────┐
 │ $ 16.75          │   │ 稅費    $ 1.00│
 └──────────────────┘   └──────────────┘
  含稅合計 $17.75

  主分類  🏠 租屋  ☂ 保險  ☕ 外食  🛒 超市 ...
```

- 金額卡與稅費卡並排，共用同一組鍵盤；點哪一格焦點就去哪一格（沿用現有的
  `EntryDraft.field` 機制，`AmountField` 從三態縮回 `'amount' | 'tax'`）。
- 金額卡下面那一行（現在的 `currency-hint`）改名為 `amount-hint`，兩種文案：
  - 稅費是 0 或空白：**`金額請填稅前`**
  - 稅費 > 0：**`含稅合計 $17.75`**
- **收入**：稅費卡不出現，金額卡佔滿整行；`amount-hint` 也不顯示（收入沒有稅前稅後之分）。
- **移除**：幣別 chip 那一排（`currency-CAD` / `currency-TWD` / `currency-USD`）、
  「實際扣款 CAD」卡與它的展開動畫（`field-cad`、`cad-panel`）。

### 擋錯

| 情況 | 行為 |
| --- | --- |
| 金額 0 | 存不了（既有規則，不變） |
| 稅費留空或 0 | 正常存檔，不記 `taxCents` |
| 稅費大於金額 | **允許**。稅現在是外加的，沒有上限可言 |
| 收入 | 稅一律 0，不論草稿裡曾經打過什麼 |

v1.3.0 的「稅不能大於金額」這條規則連同 `taxError` 一起刪掉——它成立的前提是稅在金額**裡面**，
這個前提沒有了。

## `entryDraft` 的變化

保留：

- `EntryDraft.currency`（一律 `'CAD'`）與 `Txn.currency`、`Txn.actualCadCents`、
  Sheet 的幣別欄與實扣欄。**這是「未來可以擴展」的本體**：資料層完好，要把多幣別加回來時
  不必碰 Sheet、不必 migration。

新增：

```ts
/** 含稅合計＝稅前＋稅。存進去的就是這個數字 */
export function totalCents(d: EntryDraft): number {
  return toCents(d.amount) + taxCents(d);
}
```

修改：

- `taxCents(d)`：`d.kind === 'income'` 時回 0。一個地方擋住，卡片、合計、儲存全部跟著對。
- `actualCadCents(d)`：回 `totalCents(d)`（一律 CAD，不再分幣別）。
- `toInput(d)`：`amountCents` 與 `actualCadCents` 都是 `totalCents(d)`，`currency: 'CAD'`，
  `taxCents: taxCents(d) || undefined`。
- `draftFromTxn(cats, t)`，依序判斷：
  - **收入**：`amount = centsToInput(t.amountCents)`，稅留空。不可以減掉 `taxCents`——
    v1.3.0 的稅費卡在收入時也看得見，雪雪大人有可能已經記過一筆帶稅的收入；
    減掉的話那筆收入會在編輯時無聲地變小。這樣帶入之後再存一次，那個不該存在的稅也順手清掉了。
  - **支出、`t.currency === 'CAD'`**：`amount = centsToInput(t.amountCents − (t.taxCents ?? 0))`
  - **支出、其他幣別（舊紀錄）**：`amount = centsToInput(t.actualCadCents)`，稅留空
  - 三種情況 `currency` 都帶 `'CAD'`——存下去就完成轉換，原幣不留（使用者選的）
- `canSave(d)`：金額 0 擋下；不再檢查 `taxError`。外幣那條「實扣不能是 0」隨幣別介面一起消失。

刪除：

- `EntryDraft.cad`、`needsCadField`、`setCurrency`、`preTaxCents`、`taxError`，連同它們的測試。
  這些都是為「稅在金額裡面」與「實扣 CAD 欄」寫的，未來要把多幣別加回來時版面已經不同，
  留著一個為舊版面寫的函式沒有價值——留的是資料欄位，不是這些 helper。
- `domain/money.ts` 的 `formatOriginal` 與它的測試（只服務明細列那行小字）。

## 明細列

右下角 `formatOriginal(...)` 那個 span 整個移除，金額改用 `formatCad(cents, 'plus' | 'minus')`
帶出 `+$5.20` / `-$16.75`。稅不顯示在明細列（2026-09-22 已確認）。

## 舊資料與跨版本

- **舊的外幣紀錄放著不動**：統計本來就取 `actualCadCents`，不受影響；明細列顯示的也一直是
  那個數字，只是不再標「1,280 TWD」。
- **一編輯就轉成 CAD**：金額欄帶入 `actualCadCents`，存檔後該列的金額欄與幣別欄變成
  `58.00` / `CAD`，原本的 `1280.00` / `TWD` 消失。使用者明確選了這個做法。
- **雪雪大人那支手機還沒更新時**：她仍然看得到幣別切換、仍然記得了 TWD。資料不會壞——
  欄位都還在，新版讀得回來。兩邊畫面不一樣，等她更新就一致。
- **新版記的帳舊版讀得到**：幣別 `CAD`、實扣＝金額，跟舊版自己記的 CAD 帳長得一樣。
