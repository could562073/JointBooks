## B. 新增的範圍

### B-1 分類管理頁加「支出／收入」分段切換

- 分類與月預算子頁的標題列下方加一組分段控制：**支出 ｜ 收入**。
- 樣式與互動**完全比照統計頁的「週／月／年」**：白色獨立滑塊、`translateX` 位移
  420ms `cubic-bezier(.22,1,.36,1)`、文字顏色 240ms 淡轉、按鈕本身不各自變底色（即 MOTION 32 的規格）。
- 切換時分類卡清單整區水平滑入，比照 MOTION 8 的方向性位移
  （`translate3d(±38px,0,0)→0` + opacity `.35→1`，420ms 同曲線）。
- 「新增分類」按鈕新增的分類，`kind` 跟隨當前分段。

### B-2 收入分類的資料模型

原型的「支出／收入」分段只是視覺滑塊，切過去分類完全沒變 —— §5 的
「收入模式的子分類換成薪資、退稅、獎金、其他」從未被實作。定案如下：

- 分類新增 `kind: 'expense' | 'income'` 欄位。
- **收入側預設只有一個主分類「收入」**，`icon: 'coin'`，子分類為
  `薪資、退稅、獎金、其他`。這與 §5 的記帳面板行為、以及 §14.4 的 `main: '收入'` 完全一致。
- 使用者可在分類管理頁的「收入」分段自行新增更多收入主分類。
- **收入分類沒有預算**：分類卡不顯示金額 pill；統計頁的「預算使用」只列 `kind==='expense'` 的分類。
- 記帳面板切到「收入」時，主分類 chip 只列 `kind==='income'` 的分類；切回「支出」同理。

### B-3 記一筆面板的主分類／子分類可收合

擁有者決議：**主分類與子分類區可收起，預設收起。** 這同時解掉了面板在 390×844 裝不下的問題
（實測：390 寬時數字鍵盤最後一列 `.` `0` `⌫` 被切出畫面，430×932 才完整）。

- 收起態是一列摘要，樣式**比照既有的「日期」欄**：
  左側小標「分類」，右側顯示目前選取的 `圖示 + 主分類 · 子分類`，行尾 `▾`。
- 點摘要列展開兩個 chip 區（主分類格 + 子分類格 + 兩顆虛線「＋ 新增」）；
  展開時摘要列套 `inset 0 0 0 2px #B7A6E5`、`▾` rotate 180°；選完子分類即自動收合。
- 動畫沿用 MOTION 38（日期選擇器）的規格：
  面板 `translateY 10px→0` + opacity，240ms `cubic-bezier(.2,.8,.2,1)`；`▾` rotate 220ms ease-out。
- **驗收條件**：iPhone SE 375×667 在收起態下，數字鍵盤四列與儲存鍵必須完整可見且不溢出。

## C. 資料模型定案

### C-1 紀錄與分類以 id 關聯

擁有者決議：紀錄表與分類 **id 關聯**；分類改名時既有紀錄的顯示要連動；
分類刪除採**假刪**，不影響既有紀錄；且要能在 Sheets 裡手動調整紀錄的分類。

```ts
export type CategoryKind = 'expense' | 'income';

export type SubCategory = {
  id: string;        // uuid v4
  name: string;
};

export type Category = {
  id: string;              // uuid v4
  kind: CategoryKind;
  name: string;
  icon: IconKey;           // 15 個 Fluent key 之一
  budgetCents: number | null; // 整數分；kind==='income' 時為 null
  subs: SubCategory[];        // 至少一個
  colorSet: number;           // PALETTE 索引，可超過 5，取用時取模
  order: number;
  active: boolean;         // false = 假刪
};

export type Txn = {
  id: string;              // uuid v4，App 產生
  date: string;            // YYYY-MM-DD，使用者本地時區
  mainId: string;          // → Category.id
  subId: string;           // → SubCategory.id
  mainName: string;        // 寫入當下的名稱快照，供人閱讀 Sheet
  subName: string;         // 同上
  amountCents: number;     // 原幣金額，整數分
  currency: 'CAD' | 'TWD' | 'USD';
  actualCadCents: number;  // 實際扣款 CAD，整數分；CAD 時等於 amountCents
  by: '我' | '妻';
  note: string;            // 可為空字串
  createdAt: string;       // ISO 8601，新增時寫入一次，之後永不變動；明細依此升冪排序
  updatedAt: string;       // ISO 8601，衝突判定用
  deleted: boolean;        // 軟刪除
};
```

**顯示規則**：一律以 `mainId`／`subId` 查當前分類名稱來顯示。查得到就用當前名稱（→ 改名自動連動，
包含 `active:false` 的假刪分類）；查不到（例如在 Sheets 手動填了不存在的 id）才退回 `mainName`／`subName` 快照。

**統計聚合**：一律以 `mainId` 分組、以 `actualCadCents` 加總。假刪的分類仍會出現在統計裡
（因為歷史紀錄還指向它），但不出現在記帳面板的選單、也不出現在預算清單。

### C-2 分類改名時的 Sheet 名稱快照

**與 §14.7 的「分類改名時，紀錄頁已寫入的字串不要回頭批次改」衝突。**
§14.7 是在「字串關聯」模型下寫的建議；改用 id 關聯後，UI 顯示不需要批次改也會正確。
但擁有者要求 Sheet 能手動編輯、要好讀，所以名稱欄不能長期是舊名字。

定案：**改名後排入一次 best-effort 的背景 `batchUpdate`，只改該分類的名稱欄。**
- UI 不等它，改名當下就靠 id 解析顯示正確。
- 失敗不重試、不阻斷、不提示；下次改名或手動整理時會再補上。
- 超過 5000 列時放棄批次改（只改前 5000 列），避免配額問題。

## D. 邏輯修正（原型數據不可信）

擁有者決議：**原型的計算數據只是示意，邏輯以正確為優先。**

- **D-1 統計倍率**：§6 的「年維度 ×11.4」無來歷，判定為筆誤。
  改為 **週 = 月預算 × (7 / 該月天數)**、**月 = ×1**、**年 = ×12**。
- **D-2 原型示範資料自相矛盾**（日常頁支出 $3,712／結餘 $2,074，統計頁同為「月」卻是
  $3,742／$2,044）：實作用同一份資料算，兩頁必然一致。B 類截圖比對只比視覺，不比數字。
- **D-3 統計維度的期間定義**（月結日固定 1 日、週起始固定週一之後）：
  - 週 = 本週一 00:00 至下週一 00:00（ISO 週）。趨勢 X 軸的 `W27` 用 **ISO 週數**。
  - 月 = 當月 1 日至次月 1 日。
  - 年 = 1/1 至次年 1/1。
  - 「與上期比較」= 同長度的前一個期間。
- **D-4 日常頁結餘卡副標**：月結日固定 1 日，副標固定顯示「本月」，不顯示區間。
- **D-5 count-up 觸發**：日常頁三卡是整月合計，點不同日期不重跑；新增／編輯／刪除紀錄
  導致整月合計改變時，三卡跑 900ms（MOTION 31）。當日總額另外跑 480ms（§11-20）。
- **D-6 金額運算一律整數分（cents）**，顯示時才除 100（§14.7）。
- **D-7 日期一律用使用者本地時區產生 `YYYY-MM-DD`**，不得用 UTC（§14.7）。

## F. 架構決策

- **F-1 邀請簽章**：純前端 PWA 無法安全保存密鑰。採**方案 (a)**：
  `t` 只放過期時間戳（`base64url(exp)`），不做密碼學簽章；安全性依賴 `spreadsheetId` 難以猜測。
  過期判定在前端做（`exp < now` → 顯示「這個邀請已失效」）。
  這是刻意接受的取捨，需在 README 註明。
- **F-2 部署**：優先找永久免費網域；沒有就用 **GitHub Pages**。
  → GitHub Pages 只能靜態，`/join` 路由需 SPA fallback（`404.html` 複製 `index.html`）。
  OAuth redirect URI 需為 `https://<user>.github.io/<repo>/`（含子路徑），Vite 需設 `base`。
- **F-3 Google Cloud 專案由擁有者建立**（已有類似專案，非阻礙）。
  scope 只要 `https://www.googleapis.com/auth/drive.file` + `openid email profile`。
- **F-4 推播**：第一版**不做 Web Push**。
  「對方記帳時通知我」開關控制的是「前景輪詢偵測到對方新增時要不要顯示 toast」。
  輪詢：App 回到前景、下拉重整、以及前景每 60 秒一次。真 Web Push 延後。
- **F-5 A 類測試 24**（`scrollHeight <= clientHeight + 1`）在記一筆面板收合分類區（B-3）後才成立，
  必須連同 B-3 一起驗收，且新增 **375×667** 為第三個測試斷點。
